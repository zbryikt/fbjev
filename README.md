# fb-jev

A Chrome extension that reads your Facebook feed as it loads and asks a model
what each post actually is.

Five judgements per post, each a probability from 0 to 1:

 - **AI** — the text was generated by a language model
 - **Ad** — commercial promotion
 - **Troll** — coordinated or content-farm material: throwaway pages, outrage bait, filler
 - **Hate** — incitement against a group or identity
 - **Noob** — the poster does not appear to understand the context they are posting into

Anything scoring above the threshold gets dimmed and folded down to a single line,
leaving only who posted it. Click the badge to expand.

Judgement is done by [jev](https://docs.typesafe.ai/), TypeSafe's System One model.


## Install

There is no packaged release. Build it and load it unpacked:

    npm install
    npm run build

Then in Chrome: `chrome://extensions` → enable Developer mode → **Load unpacked** →
select the **`web/static`** directory (not the project root).

Open the popup from the extensions menu to configure it.


## Configuration

Everything lives in the popup and saves on change; there is no save button.

 - **Source** — `mock` or `jev`. Falls back to `mock` whenever the API key is empty
 - **API endpoint** — defaults to `https://api.typesafe.ai/v1/systemone`
 - **API key** — stored in `chrome.storage.local`, never written to disk or into the page
 - **Model** — defaults to `jev-latest`; pin a version such as `jev-1.13.0` if you prefer
 - **Threshold** — score at or above which a post counts as a hit. Defaults to `0.5`
 - **Badge / fold** — either behaviour can be turned off independently

The `mock` source is a local keyword heuristic. It is deliberately crude, and it exists
so the whole pipeline runs without an API key: useful for verifying DOM extraction and
UI changes without paying for a request per post.


## How it works

Three execution contexts share a `fbjev` global. LiveScript is compiled with `bare: true`,
so each file's top level is the global scope and there is no module system.

 - **content script** — a `MutationObserver` finds newly mounted posts, an
   `IntersectionObserver` narrows them to the ones actually scrolled into view.
   Only those get sent for judgement, which is by far the biggest saving on API calls
 - **service worker** — the single exit point for judgement requests. Holds the API key,
   a fingerprint cache, and a queue capped at three concurrent requests. Living here means
   the key never enters the page, the cache is shared across tabs, and `fetch` is not
   subject to Facebook's CSP
 - **popup** — settings and local counters

Posts are identified by a djb2 fingerprint of author plus the first 400 characters of the
body, not by DOM node. Facebook's feed is a virtualised list: nodes are recycled to hold
the next post, so a "seen" flag on the element would silently drop everything that scrolls
past. The fingerprint also serves as the cache key, so a post re-mounted during scrolling
costs nothing.

A "Follow" control in the author row means Facebook suggested this post rather than the
reader subscribing to it, and that flag is sent along with the body. Short posts are judged
too — a hook of a few words from a suggested page is exactly the case worth catching — with
the "See more" button text stripped so it does not pad the length.

Extraction anchors on `data-ad-rendering-role` and `div[data-virtualized]` rather than
class names, which are minified and change with every Facebook release. All selectors live
in `web/src/ls/lib/post.ls`; that is the file to fix when a Facebook update breaks things.


## The API

    POST https://api.typesafe.ai/v1/systemone
    Authorization: Bearer <key>

The `noul` question type takes a yes/no proposition and returns a probability directly,
so there is no asking a model to emit JSON and no parsing of prose. Five dimensions means
five questions in one request, roughly 800 input tokens per post. The response is
`{model, answers: {<id>: {noul}}, usage}`.

`429` and `529` are documented as transient; the client backs off once and then gives up
rather than holding up the queue for a post the reader has already scrolled past.

Adding a dimension means editing `analyzer.dimensions` and `jev.questions`, plus one line
in the popup markup for its counter. Badges, folding and statistics all follow from there.


## Known limitations

The "Sponsored" label is not readable. Facebook's `meta` region contains only an obfuscated
domain string, and the label itself is in no node that can be queried — recovering the
visible text does not help either. No `sponsored` field is sent to the model: a flag that
is permanently false would assert "this is not an ad", which is worse than omitting it.
In practice the model identifies ads from the body text well enough.

Judgement sees the post body, the author name, and whether the post came from a page the
reader does not follow. That last one is the strongest DOM-level signal available: people
you actually follow are not the problem. The rest of what would help — account age,
follower count, posting frequency — lives on the page, not in the post, and is not
collected yet.

Image-only and video-only posts are skipped; there is no text to judge. This matters more
than it sounds: jev accepts text only — images, audio and video are not supported — so for
a post whose substance is a meme or a screenshot, the most important evidence never reaches
the model.

Very short posts are judged, but barely on their own content. With little text the scores
drift toward 0.5, which in `noul` terms means genuine uncertainty rather than "half true".
What separates them in practice is context outside the body: the account name and whether
the post came from a page the reader does not follow. Bear that in mind when setting the
threshold — a value of 0.5 treats "the model does not know" as a hit.


## Development

    npm run build        # one-shot build of web/src into web/static
    npm start            # same, plus watch

Source is LiveScript, Pug and Stylus, built by `@zbryikt/template`. `web/static` is
entirely generated and can be deleted at any time. After rebuilding, reload the extension
from `chrome://extensions`; changes to the content script also need the Facebook tab
refreshed.

Note that an extension reload orphans the content script in any already-open tab. In that
state `chrome.runtime.sendMessage` throws synchronously rather than rejecting, so a `.catch`
will not see it — the watcher traps this, stops observing, and logs a request to refresh.
